# 고용전망 아카이브

국내외 주요 기관의 고용·성장·물가 전망치를 모아 발표 회차별 수정 이력과 함께
조회하는 비공식 개인 아카이브. 기획: `고용전망_아카이브_기획서.md`

> 본 서비스는 개인이 제작한 비공식 참고자료이며, 각 기관 원문이 정본입니다.

## 구조

- `core/` — 도메인 공통 껍데기(토큰·기본 스타일·셸 유틸). 원본은 여기 하나뿐이며
  빌드 시 사이트 루트와 각 도메인 폴더로 복사된다
- `hub/` — 4개 영역 런처. 도메인의 `data/last_run.json` 유무로 활성/준비중을 판정한다
- `domains/<이름>/` — 도메인 수직 슬라이스. `app/`(화면) `data/`(데이터)
  `pipeline/`(수집기) `tests/`
- `tools/build.py` — 사이트 조립. 배포와 로컬 서버가 이 함수를 공유한다
- `.github/workflows/` — 도메인별 수집 + Pages 배포

## 전망 수집기

| 기관 | 경로 | 지표 | 비고 |
|---|---|---|---|
| OECD 본편 | SDMX 회차별 데이터플로(`DF_EO_116`~, 최신 `DF_EO`) | 성장·물가·실업·취업자 | `verified`, 원문 링크는 OECD 정기간행물 목록에서 찾은 Economic Outlook 보고서 주소 |
| OECD Interim | 보고서 PDF (3월·9월) | 성장·물가 | 표가 90도 회전돼 좌표 순서로 복원 |
| IMF | DataMapper(현행) + SDMX 보관 회차 | 성장·물가·실업 | 보관 회차는 2025년 10월판 하나뿐, 원문 링크는 발표일로 조립한 WEO 보고서 주소 |
| 한국은행 | 게시판 RSS → 본문 → 첨부 PDF | 5개 전부 | 반기 포함 |
| KDI | `/research/economy` → 장별 PDF | 4개 | **사이트 502 중단** |
| 한국노동연구원 | 노동리뷰 특집 → 첨부 PDF | 취업자·실업률·고용률 | 반기 포함 |
| 산업연구원 | 경제·산업 전망 → 첨부 PDF | 성장률 | 고용 전망표 없음 |
| 한국고용정보원 | 고용동향브리프 목록 → 첨부 PDF | 취업자·실업률·고용률 | PDF 에 텍스트 레이어가 없어 OCR 로 읽는다, 반기 포함 |

`published_at` 은 **기관의 실제 발표일**이다. API 수집기(OECD·IMF)도 수집일이 아니라
회차 발표일을 넣는다 — 그래야 기관 간 수정 이력이 같은 의미를 갖는다. 회차를 스스로
밝히지 않는 API 는 수집기 안의 표(`EDITIONS`)로 발표일을 관리하며, 모르는 회차가 오면
조용히 틀린 날짜를 쓰지 않고 실패한다.

텍스트 레이어가 있는 PDF 는 요약표 한 페이지만 읽는다(`pipeline/pdf.py`). 표의 열
구성이 기관·회차마다 다르므로 열 위치를 고정하지 않고 헤더의 연도·기간 토큰으로 열을
복원하며, 어긋나면 조용히 넘기지 않고 실패시킨다. API 수집기(OECD·IMF)도 수치는
API 에서 가져오지만 저장하는 원문 링크는 API 응답이 아니라 기관이 펴낸 보고서 페이지다
— 원문 보기를 누른 사람이 실제로 읽을 수 있는 곳에 닿아야 하기 때문이다. 한국고용정보원의 PDF 는 InDesign 이
글자를 전부 아웃라인으로 내보내 텍스트 레이어가 아예 없어, 쪽을 렌더링해 OCR 로
읽는다(`pipeline/ocr.py`). 반기 전망도 함께 저장한다(연간 id는 그대로 두고 반기만
뒤에 `-h1`·`-h2`를 붙인다). 집계·비교·타임라인은 연간 기준이고, 반기는 홈 카드와
기관 상세에 참고로만 붙는다. 반기를 내지 않는 기관은 `-` 로 표시한다.

한국고용정보원 수집기를 로컬에서 돌리려면 `tesseract-ocr` 과 한국어·영어 언어팩
(`tesseract-ocr-kor`, `tesseract-ocr-eng`)이 시스템에 설치돼 있어야 한다 — `pip install`
만으로는 안 들어온다. CI 는 `collect-forecast.yml` 에서 apt 로 설치한다.

### 소급 수집(백필)

`python -m domains.forecast.pipeline.backfill [기관...]` — 지나간 회차를 1회성으로
채운다. 일상 수집기는 최신 회차 하나만 보므로 아카이브 시작 전 회차는 이 경로로만
들어온다. CI 에 넣지 않는다. 설계는 `docs/superpowers/specs/2026-08-30-전망-국내기관-백필-design.md`.

수집 실패는 `data/last_run.json` 에 한 줄로 남고 워크플로가 그날 실행을 빨갛게 만든다.
원인을 이미 아는 외부 장애는 `collect-forecast.yml` 의 `KNOWN_DOWN` 에 `kdi@2026-09-30`
처럼 기한과 함께 적어 통과시킨다 — 오래 죽은 수집기 하나 때문에 매일 빨개지면 다른
수집기가 깨진 날을 놓친다. 기한이 지나거나 그 수집기가 되살아나면 다시 빨개지므로,
유예를 지우거나 미루기 전에는 초록으로 돌아가지 않는다(`pipeline/check_run.py`).

## 고용동향 수집기

| 출처 | 경로 | 분류 | 비고 |
|---|---|---|---|
| 경제활동인구조사 | 국가데이터처 보도자료 게시판 → 첨부 xlsx | 산업별·성별·연령별 | KOSIS API 미사용(원계열 월별 산업별 취업자가 2024-12 에서 끊긴다) |
| 사업체노동력조사 | KOSIS OpenAPI (`DT_118N_MON066`) | 산업별만 | 성·연령별 종사자수를 발표하지 않는다 |
| 고용행정통계 | 고용노동부 보도자료 게시판 → 첨부 hwpx | 산업별·성별·연령별 | 표는 인덱스가 아니라 헤더로 찾는다(회차마다 표 개수가 다르다) |

세 출처 모두 산업별을 낸다. 성별·연령별은 경제활동인구조사와 고용행정통계만
낸다 — 사업체노동력조사 열은 화면에서 `―`(미제공)로 표시되고, 표 자체가 발표되지
않는 것과 그 달치 발표가 아직 나오지 않은 것(미발표)은 다른 상태로 구분한다.

## 고용동향 화면

`domains/employment/app/` — 총괄·속성별·출처비교 세 화면과, 표 상단에서 여는
증감 비교 시트로 구성된다. 총괄은 최신 달 카드(미발표 출처는 직전달 값을 회색으로
붙인다), 속성별은 산업·성·연령 토글과 정렬·펼침, 출처비교는 같은 지표를 세 출처가
어떻게 다르게 내는지 나란히 본다. 연·월 스위처의 하한은 세 출처가 모두 값을 가진
첫 달로 정해진다.

수집 실패는 `data/last_run.json` 에 한 줄로 남고 `collect-employment.yml` 이 그날
실행을 빨갛게 만든다. `KNOWN_DOWN` 형식은 전망 수집기와 같다.

## 실행

```bash
pip install -r requirements.txt
python -m pytest                              # 파이썬 테스트 (네트워크 불필요)
node --test "core/tests/*.mjs" "hub/tests/*.mjs" "domains/forecast/tests/web/*.mjs" "domains/employment/tests/web/*.mjs"   # 웹 테스트
python -m tools.serve                         # 로컬 서버 (http://127.0.0.1:8642/)
python -m domains.forecast.pipeline.collect   # 전망 수집 1회
python -m domains.employment.pipeline.collect   # 고용동향 수집 1회 (KOSIS_API_KEY 필요)
```

웹앱은 `python -m tools.serve` 로 조립된 사이트를 그대로 띄운다. 앱 폴더의 `index.html`을
`file://`로 직접 열면 `./core/` 참조가 깨지므로 반드시 이 서버를 쓴다.
