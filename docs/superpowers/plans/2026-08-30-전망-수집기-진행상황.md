## 2. 확정된 설계 결정 (되돌리지 말 것)

- **`published_at` 은 기관의 실제 발표일이다.** 수집일이 아니다. API 수집기
  (OECD·IMF)도 회차 발표일을 넣는다. 그래야 기관 간 수정 이력이 같은 의미를 갖는다.
- **회차를 스스로 밝히지 않는 API 는 수집기 안의 표로 발표일을 관리하고, 모르는
  회차가 오면 실패시킨다.** 조용히 틀린 날짜를 붙이지 않는다.
  - `oecd.EDITIONS` — 회차 번호 → 발표일
  - `imf.EDITIONS` — 전망 지평 마지막 연도 → 발표일
  - `oecd_interim.EDITIONS` — 회차 라벨 → (발표일, PDF)
- **백필 범위는 발표일 `2024-11-01` 이후 전 회차.** 자동 판정을 쓰지 않는 이유는
  스펙 2절 참조.
- **백필은 `collect.drop_unchanged` 를 쓰지 않는다.** 전역 최신값과 비교해 과거
  회차를 조용히 버린다. `store.merge` 가 id 로 중복을 거른다.
- **백필 끝에 `store.recompute_revisions` 를 돌린다.** 과거 회차가 나중에 들어오면
  먼저 저장돼 있던 회차의 수정폭이 빈 채로 남는다.
- **수집기는 `list_issues()` / `collect_issue(issue)` 두 단계**로 나눈다. 일상
  수집은 `collect_issue(list_issues()[0])`. 백필이 같은 함수를 범위로 순회한다.

## 3. 남은 일 (권장 순서)

### ① 기획재정부 — 목록 접근 경로가 막혀 있다

경제정책방향은 취업자 증감 전망을 실어 이 아카이브에 값이 크다. **HWP 파싱 자체는
문제가 아니다** — 다른 작업에서 표준 라이브러리(`zipfile` + `xml.etree`)로 hwpx 를
읽는 것이 이미 확인됐다(`docs/superpowers/spikes/2026-08-30-고용행정통계-보도자료-파싱.md`).

막힌 곳은 **회차 목록**이다. 확인한 것:
- 보도자료 게시판: `https://www.moef.go.kr/nw/nes/nesdta.do?bbsId=MOSFBBS_000000000028&menuNo=4010100` (200)
- 검색 폼은 `name="searchFrm"`, `action="/sch/schMain.do"`, 입력 `kwd`·`searchCondition`
- `GET /sch/schMain.do?kwd=...` 로는 결과가 안 나온다 (JS 또는 POST 기반으로 보임)

다음 시도: 브라우저 네트워크 탭으로 실제 검색 요청을 확인하거나(`claude-in-chrome`),
게시판의 페이지네이션 파라미터로 목록을 훑어 제목에 '경제정책방향'이 있는 회차를 찾는다.

### ② 고용정보원 (KEIS) — LLM 트랙, 설계 먼저

`orgs.json` 에서 유일한 track B / method `llm` 이다. 착수 전에 정해야 할 것:
- 새 `confidence` 등급이 필요한가(`verified`/`extracted` 외에 `inferred` 등)
- 화면에서 어떻게 구분해 보일 것인가
- 원문 근거(쪽·문장)를 어디까지 남길 것인가

이건 데이터 신뢰도 모델을 건드리므로 브레인스토밍을 먼저 거친다.

### ③ ADB — 값이 작다

`https://www.adb.org/countries/korea/economy` 는 JS 렌더링이고 `<table>` 이 0개다.
ADO 본편 PDF 를 파싱해야 하며 지표는 성장률·물가 2개뿐이다(고용 없음). 후순위.

### ④ 한국은행 2025년 11월호 — 폴백

요약표(p11) 행 이름이 벡터 도형이라 OCR 없이 못 읽는다. 장별 표에는 라벨이
텍스트로 있으나 **숫자 줄이 라벨 줄보다 먼저** 오는 배치다. 스펙 6절에 상세.

### ⑤ KDI — 서버 복구 대기

`KNOWN_DOWN: kdi@2026-09-30` 이 걸려 있다. 복구되면 워크플로가 빨개지며 지우라고
알린다. 우회 경로는 없음이 확인됐다(스펙 2절). 복구 후 `kdi.list_issues()` 를
구현하면 된다 — 연도 선택 `<select>` 의 `option value` 가 회차 식별자다.

## 4. 함정 (다시 밟지 말 것)

- **목차·본문 참조에도 표 캡션이 나온다.** `<표 1-6> … 36`, `Table 1. Global
  growth … 6`. 첫 매칭 페이지를 표로 믿으면 실패한다. 쪽 단위로 실패를 가둔다
  (`kiet`·`kli`·`oecd_interim` 모두 이 처리를 한다).
- **표 캡션 줄의 기간 낱말이 헤더로 딸려 들어간다.** "…하반기 및 … 연간 고용
  전망" → 열 복원이 어긋난다. 표 구간을 자를 때 캡션 줄은 뺀다.
- **KLI 표는 천명 단위**다. 만명으로 환산한다. '취업자' 수준 행이 아니라
  '(증감수)' 행을 쓴다.
- **OECD `target_years` 는 수집일이 아니라 데이터의 마지막 두 해**로 정한다.
  12월 회차는 다음 두 해를, 6월 회차는 당해와 다음 해를 전망한다.
- **`_data_url(최신 회차)` 는 `DF_EO` 를 써야 한다.** `DF_EO_119` 는 존재하지 않는다.
- **윈도우 콘솔은 cp949 다.** `python -m` 진입점은 `sys.stdout.reconfigure(
  encoding="utf-8")` 를 해야 출력하다 죽지 않는다.
- 로컬 실행 시 `PYTHONIOENCODING=utf-8` 을 걸지 않으면 한글 출력이 깨져 보인다.
