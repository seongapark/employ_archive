# 출처 탐색(lookup) 구현 계획

> **For agentic workers:** 이 계획은 이 세션에서 순차로 실행한다. **태스크 1~2 를 끝내면 멈추고 FTS 검색 결과를 보고한 뒤** 3 으로 간다.

**Goal:** 질문을 넣으면 **"이 질문에는 이런 출처가 답이 될 수 있으니 살펴보라"** 를 도메인별로 내놓는다. 문장으로 답하지 않는다.

**Architecture:** D1 에 FTS5 가상테이블을 두고 초록·목차·전망근거·카탈로그 설명을 색인한다. 워커는 질문을 그 색인에 던져 도메인별 결과 묶음(출처 제목·매치 스니펫·링크)을 낸다. **LLM 을 부르지 않는다.** 고용동향만 FTS 가 아니라 `observation` 조회 결과를 같은 형식으로 낸다.

**Tech Stack:** Cloudflare D1 (SQLite FTS5) · Cloudflare Workers (ESM `.mjs`) · Python 3.12 (적재) · `node --test` · `pytest`

**Spec:** `docs/superpowers/specs/2026-09-10-질의응답-도메인취합-design.md` 의 §7(데이터 경로)·§8(카탈로그)만 쓴다. §3·§4·§6(답변자 계약·취합기·문장 검증)은 이 계획의 범위가 **아니다**.

## 왜 방향을 바꾸는가

원래 목적은 네 도메인(동향·전망·모니터링·연구보고서) 자료를 **한 허브로 모으는 것**이었고, 질의응답은 거기서 파생된 기능이다. 지금 실제로 부족한 것은 "답을 문장으로 써 주는 것" 이 아니라 **"질문에 맞는 출처를 빨리 찾는 것"** 이다(2026-09-10 사용자 판단).

검색이 안 되던 원인은 용량이 아니라 **초록·목차·전망근거가 애초에 검색 대상이 아니었다**는 것이다. 그 셋은 D1 에 없었고, 있는 것(`observation`·`forecast`)도 전문 검색 색인이 없었다.

그래서 단계 A 계획(`2026-09-10-질의응답-도메인취합-A.md`)의 LLM 취합기·문장 단위 검증·골든 회귀(태스크 5~7·10)는 **보류한다.** 문서는 지우지 않는다 — 나중에 "이 출처들로 요약" 을 얹을 때 그대로 쓴다.

## 규모 판단 (2026-09-10 실측)

| 대상 | 크기 | 판단 |
|---|---|---|
| `reports.json` 572건 | 378KB | 담는다 |
| `abstracts.json` 초록 총 50만 자 | 1.7MB | 담는다 |
| `forecast_rationale` 53건 | 수십 KB | 담는다 |
| 원문 PDF 본문 전체 | 450건 · 약 39,000쪽 추정 · trigram 색인 포함 0.5~1GB | **하지 않는다** — D1 무료 플랜(500MB)을 넘는다. 필요해지면 그때 |

D1 무료 플랜은 DB 500MB 다. 위 셋을 다 담아도 2MB 남짓이라 문제없다. **폐쇄망 이식은 고려하지 않는다 — D1 하나로 간다.**

## Global Constraints

- **LLM 을 부르지 않는다.** `ASK_API_BASE`·`ASK_MODEL` 설정은 남기되 코드가 참조하지 않는다.
- **꼭 필요한 기능만 만든다.** 다양한 시나리오 대비 코드 금지.
- **`core/ask.mjs` 를 지우지 않는다.** 지금 답변 로직이 거기 있고, 나중에 "이 출처들로 요약" 버튼을 얹을 때 그대로 쓴다. 이 작업에서는 호출하지 않는다.
- 적재는 **재실행 가능**해야 한다(id 기준 upsert). D1 문장 100KB·바인딩 100개 제한을 지켜 배치로 넣는다.
- 테스트는 네트워크에 나가지 않는다.
- 커밋 메시지는 한국어. 끝에 `Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>` 와 `Claude-Session:` 두 줄.

**Files:**

**Interfaces:**

**왜 한 표에 다 넣는가.** 도메인마다 표를 쪼개면 질문 하나에 네 번 조회하고 순위를 손으로 합쳐야 한다. 한 표에 `도메인` 열을 두면 한 번 조회하고 도메인별로 나누기만 하면 된다.

- [ ] **Step 1: 마이그레이션을 쓴다**

```sql
-- domains/ask/worker/migrations/0004_fts.sql
-- 초록·목차·전망근거·카탈로그 설명을 한 색인에 담는다. 도메인은 열로 가른다.
--
-- 토크나이저가 trigram 인 이유: 한국어는 공백 토큰화로 부분일치가 안 된다.
-- "청년고용" 으로 색인된 문서가 "청년 고용" 검색에 안 걸리고 그 반대도 마찬가지다.
-- trigram 은 세 글자씩 잘라 담아 그 문제를 없앤다. 대신 색인이 커진다(본문의 3배쯤).
CREATE VIRTUAL TABLE doc_fts USING fts5(
  doc_id UNINDEXED,
  도메인 UNINDEXED,
  종류   UNINDEXED,
  제목,
  본문,
  tokenize = 'trigram'
);
```


Expected: 성공. `no such tokenizer: trigram` 이면 Step 3 으로.

- [ ] **Step 3: trigram 이 없으면 unicode61 로 내리고 그 사실을 남긴다**

`tokenize = "unicode61 remove_diacritics 2"` 로 바꾸고, 마이그레이션 주석과 이 계획서 양쪽에 **"D1 의 SQLite 빌드에 trigram 이 없다(2026-09-10 확인)"** 를 적는다. unicode61 이면 부분일치가 약해지므로, 적재 때 제목·본문을 그대로 넣는 것 외에 **띄어쓰기를 지운 사본**을 본문 뒤에 덧붙인다(웹앱 검색이 `squash()` 로 쓰는 방법과 같다).

`tools/tests/test_fts_load.py`:

```python
from tools import fts_load


def test_a_long_abstract_is_split_into_rows_under_the_limit():
    # D1 은 한 문장이 100KB 를 넘으면 거부한다. 초록 한 건이 6천 자라 그대로도 들어가지만,
    # 스니펫을 내려면 조각이 작아야 한다 — 6천 자를 통째로 보여줄 수는 없다.
    long = ('청년 고용률이 하락했다. ' * 300)
    out = fts_load.chunks(long, limit=2000)
    assert len(out) > 1
    assert all(len(c) <= 2000 for c in out)
    assert ''.join(out).replace(' ', '') == long.replace(' ', '')


def test_chunks_break_on_sentence_ends_not_mid_word():
    text = '첫 문장이다. 두 번째 문장이다. 세 번째 문장이다.'
    out = fts_load.chunks(text, limit=20)
    assert all(c.strip().endswith('다.') for c in out), out


def test_every_row_carries_the_domain_and_a_stable_id():
    rows = fts_load.rows()
    assert rows, '저장소 데이터에서 한 행도 안 나왔다'
    ids = [r['doc_id'] for r in rows]
    assert len(ids) == len(set(ids)), '중복 id 가 있으면 upsert 가 서로를 덮는다'
    assert {r['도메인'] for r in rows} <= {'reports', 'forecast', 'catalog'}


def test_the_sql_deletes_before_inserting_so_it_can_be_rerun():
    sql = fts_load.build_sql([{ 'doc_id': 'x', '도메인': 'reports', '종류': '초록',
                                '제목': '제목', '본문': '본문' }])
    assert 'DELETE FROM doc_fts' in sql
    assert sql.count('INSERT INTO doc_fts') >= 1


def test_a_quote_in_the_text_does_not_break_the_sql():
    sql = fts_load.build_sql([{ 'doc_id': 'x', '도메인': 'reports', '종류': '초록',
                                '제목': "따옴표'가 든 제목", '본문': '본문' }])
    assert "''" in sql
```

(a) 를 기본으로 본다. 표가 못 알아들으면 그 도메인은 "해당 없음" 이 되고, 연구보고서·전망근거는 FTS 가 **질문 원문 그대로** 걸리므로 슬롯 없이도 답이 나온다.
