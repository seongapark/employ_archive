# 방문 통계와 관리자 화면 — 설계

2026-09-11. 도메인별로 얼마나 쓰이는지를 보기 위한 수집기·저장소·관리자 화면.

## 1. 무엇을 푸는가

지금 이 아카이브는 **자기가 얼마나 쓰이는지 모른다.** GitHub Pages 정적 배포라
서버 로그가 없고, 분석 도구도 붙어 있지 않다. 그래서 "고용동향에 손을 더 댈까,
연구보고서를 키울까" 같은 판단이 전부 감이다. 보류해 둔 기능(시트 툴팁, 스와이프
닫기)을 되살릴지도 마찬가지다 — 아무도 안 여는 화면이면 되살릴 이유가 없다.

푸는 것은 하나다. **도메인 다섯과 허브가 각각 얼마나, 누구에게, 어디서 들어와
쓰이는지를 한 화면에서 본다.**

## 2. 사용자가 정한 것

| 결정 | 값 | 함의 |
|---|---|---|
| 측정 깊이 | 유입·기기·재방문까지 | 일반 웹분석 수준. 방문자 식별이 필요해진다 |
| 접근 제한 | 비밀번호 한 개 | 워커에 secret 하나. OAuth 안 붙인다 |
| 방문자 식별 | 기기에 익명 ID 저장 | localStorage 난수. IP 는 안 받는다 |
| 화면 경로 | id 를 묶어 화면 단위로 | `#/b/industry/300` → `/b/industry/:id` |
| 본인 방문 | 관리자 화면에 제외 스위치 | 끄고 켜는 것도 본인이 정한다 |
| 워커 배치 | 따로 세운다 | `employ-archive-metrics`. ask 와 안 섞는다 |
| 보관 기간 | 무기한 | 지우는 cron 이 없다. 대신 방문자 표를 따로 둔다(§5.3) |
| 화면 구성 | 한 페이지 스크롤 | 탭 없음 |

## 3. 구조

```
앱 6개 (허브 + 도메인 5)
  └ core/track.js  ──sendBeacon──▶  employ-archive-metrics (워커)
                                      ├ POST /api/hit    (공개, 토큰 없음)
                                      ├ GET  /api/stats  (Bearer 토큰)
                                      └ D1: employ-archive-metrics
                                           ├ hit
                                           └ visitor
domains/admin/app/  ──Bearer──▶  GET /api/stats
  (= https://seongapark.github.io/employ_archive/admin/)
```

**ask 의 D1 과 반드시 분리한다.** `sync-catalog`·`sync-fts` 워크플로가 그 DB 의
표를 주기적으로 지우고 다시 채운다. 같은 DB 에 방문 기록을 두면 어느 날 통째로
사라지고, 무기한 보관이라 복구할 원본도 없다.

**워커도 분리한다.** 통계 쪽 예외나 폭주가 질의응답을 같이 죽이면 안 된다. 값은
첫 배포 때 `d1 create`·`secret put`·`deploy` 를 한 번 더 도는 것뿐이다(§8).

## 4. 수집 — `core/track.js`

### 4.1 붙이는 법

`tools/build.py` 가 `core/` 를 허브와 도메인 폴더 **양쪽에** 복사한다. 그래서
파일 하나를 만들면 여섯 앱이 전부 켜진다. 각 `index.html` 에 한 줄:

```html
<script type="module" src="./core/track.js" data-track-domain="employment"></script>
```

도메인은 **URL 에서 추측하지 않고 선언한다.** 경로 파싱은 로컬 서버·배포·설치앱
(standalone)에서 제각기 다르게 깨지고, 애초에 도메인 경계는 우리가 정한 것이지
URL 이 정한 것이 아니다.

쓰는 값은 여섯이다: `hub`, `employment`, `press`, `forecast`, `reports`, `ask`.
폴더 이름과 같게 둔다. `admin` 자신은 **안 붙인다** — 관리자 화면 방문이 통계에
섞이면 본인 제외 스위치가 무의미해진다.

한글 이름은 **관리자 앱이 자기 상수로 들고 있는다.** `hub/js/state.js` 의 `DOMAINS`
를 끌어 쓸 수 없다: 빌드가 각 도메인 폴더에 복사해 주는 것은 `core/` 뿐이라 배포본에
`../hub/js/state.js` 경로가 없고, 그 목록에는 `hub`·`ask` 가 애초에 빠져 있다
(허브는 자기 카드를 안 그리고, 질의응답은 카드가 아니라 검색창이라서).

**함정: 모듈 스크립트에서 `document.currentScript` 는 `null` 이다.** 그래서
`currentScript.dataset` 로 읽으면 도메인이 전부 `undefined` 가 되고, 통계가 조용히
한 덩어리로 뭉개진다(비콘은 실패해도 조용하니 눈치채지 못한다). 반드시

```js
const 도메인 = document.querySelector('script[data-track-domain]')?.dataset.trackDomain;
```

로 읽고, 없으면 **아무것도 보내지 않는다** — 정체를 모르는 줄을 쌓느니 안 쌓는다.

### 4.2 언제 보내나

첫 로드 1회, 그리고 `hashchange` 마다 1회. 앱들이 `#/b/...` 해시 라우트라서 이걸
안 잡으면 "고용동향을 열었다"까지만 알고 그 안에서 무엇을 봤는지는 못 본다 —
요청한 화면별 깊이가 통째로 사라진다.

같은 경로로의 연속 전송은 거른다(뒤로가기 연타, 라우터 재진입).

### 4.3 무엇을 보내나

클라이언트가 담는 것은 여섯 개뿐이다.

| 필드 | 값 | 비고 |
|---|---|---|
| `d` | 도메인 | §4.1 의 선언값 |
| `p` | 화면 경로 | §4.4 규칙으로 정규화한 것 |
| `r` | 유입 호스트 | `document.referrer` 의 호스트만. 같은 사이트면 안 보냄 |
| `v` | 방문자 ID | `localStorage['ea:v']`, `crypto.randomUUID()` |
| `s` | 세션 ID | `sessionStorage['ea:s']`, 같은 방식 |
| `m` | 표시모드 | `matchMedia('(display-mode: standalone)')` → `standalone`/`browser` |

**전체 경로(`location.href`)나 검색어(referrer 의 쿼리)는 보내지 않는다.** 호스트만
남기면 "구글에서 왔다" 는 알 수 있고 "무엇을 검색했다" 는 안 남는다. 후자는 우리가
쓸 데도 없으면서 남의 것이다.

**IP 는 저장하지도 해시하지도 않는다.** 방문자 ID 가 이미 있어 쓸모가 없다. 안 받아
두면 나중에 개인정보 얘기가 나올 때 설명할 것이 없다.

### 4.4 화면 경로 정규화

해시에서 `#` 을 떼고, **숫자를 포함한 세그먼트를 `:id` 로 바꾼다.**

```
#/b/industry/300        → /b/industry/:id
#/overview              → /overview
#/r/kdi/2026-01-15-4412 → /r/kdi/:id
(해시 없음)              → /
```

라우트 이름(`overview`, `industry`, `sex`)에는 숫자가 없고, 값(산업코드, 연도,
보고서 id)에는 있다. 이 비대칭이 규칙의 근거다. 세그먼트는 넷까지만 남긴다.

> 언젠가 `/top10` 같은 라우트 이름이 생기면 이 규칙이 그것을 `:id` 로 뭉갠다.
> 그때는 예외 목록 한 줄과 테스트 한 줄이면 된다. 미리 만들지 않는다.

### 4.5 안 보내는 경우

셋 중 하나라도 걸리면 전송하지 않는다.

1. `localStorage['ea:off'] === '1'` — 본인 제외 스위치(§7.4)
2. `location.hostname` 이 `localhost`·`127.0.0.1` — 개발 중 조회
3. 도메인 선언이 없다(§4.1)

**localStorage 는 오리진 단위다.** 여섯 앱이 전부 `seongapark.github.io` 라서
방문자 ID 도 제외 스위치도 앱 사이에서 공유된다. 이것은 사고가 아니라 우리가
원하는 동작이다 — 한 사람이 허브에서 고용동향으로 넘어가는 것을 한 사람으로 세야
하고, 제외 스위치는 한 번 켜면 여섯 군데 다 꺼져야 한다.

### 4.6 전송

```js
navigator.sendBeacon(ENDPOINT, JSON.stringify(payload));
```

**문자열로 보낸다.** `Blob` 에 `application/json` 을 붙이면 preflight 가 붙어 왕복이
하나 더 는다. 문자열은 `text/plain` 으로 나가 단순 요청이 되고, 서버가
`await request.text()` 후 파싱한다. `sendBeacon` 이 없으면
`fetch(..., { keepalive: true })` 로 떨어진다.

**실패는 조용히 버린다.** try/catch 로 감싸고 아무것도 다시 시도하지 않는다.
localStorage 가 막힌 브라우저(사생활 보호 모드)에서도 던지지 않고 메모리 ID 로
계속 돈다 — 그 방문은 늘 신규로 잡히지만, 화면은 멀쩡하다. **통계가 화면을 못
건드린다**가 이 파일의 유일한 불변식이다.

## 5. 저장 — `domains/admin/worker/`

### 5.1 라우트

| 라우트 | 인증 | 응답 |
|---|---|---|
| `POST /api/hit` | 없음 | 항상 `204`. 저장했는지 거부했는지 알려주지 않는다 |
| `GET /api/stats?days=30` | Bearer | 집계 JSON(§6) |
| `GET /api/health` | 없음 | `{ ok: true }` |

`/api/hit` 이 **거부 사유를 안 알려주는** 이유는 둘이다. 클라이언트가 재시도할 일이
없고, 어디서 걸렸는지 알려 주면 우회하는 법을 같이 알려 주는 셈이다.

`Origin` 헤더가 `ALLOWED_ORIGIN` 과 다르면 저장하지 않는다(역시 204).

### 5.2 봇과 남용

세 겹이다.

1. **비콘이라는 형식 자체.** JS 를 안 돌리는 크롤러는 애초에 안 들어온다. 공짜로
   얻는 1차 필터이고, 실제로 가장 크게 거른다.
2. **UA 패턴.** `bot|crawl|spider|slurp|headless|preview|monitor|curl|wget|
   python-requests|facebookexternalhit|lighthouse|pagespeed` 에 걸리거나 UA 가
   비었으면 버린다.
3. **방문자당 일일 상한 500줄.** 정상 사용으로는 닿지 않고(하루에 화면을 500번
   전환), 스크립트로 부풀리는 것은 막힌다.

**상한을 KV 로 세지 않는다.** Workers KV 는 무료 쓰기가 하루 1,000회뿐이라, 조회마다
쓰면 D1 한도(10만)보다 KV 한도에 백 배 먼저 걸린다. ask 워커가 KV 를 쓰는 것은
요청이 훨씬 드문 LLM 호출이기 때문이고, 여기에 그대로 옮기면 안 된다.

### 5.3 스키마 — `migrations/0001_init.sql`

```sql
CREATE TABLE hit (
  id       INTEGER PRIMARY KEY,
  ts       TEXT NOT NULL,   -- UTC ISO8601 (초 단위)
  day      TEXT NOT NULL,   -- KST 기준 YYYY-MM-DD  ← §5.4
  domain   TEXT NOT NULL,
  path     TEXT NOT NULL,
  visitor  TEXT NOT NULL,
  session  TEXT NOT NULL,
  ref      TEXT,            -- 유입 호스트. NULL = 직접
  ref_kind TEXT NOT NULL,   -- direct | search | social | link
  mode     TEXT NOT NULL,   -- standalone | browser
  device   TEXT NOT NULL,   -- mobile | tablet | desktop
  country  TEXT             -- 2자 국가코드. cf 가 못 주면 NULL
);
CREATE INDEX hit_day        ON hit(day);
CREATE INDEX hit_domain_day ON hit(domain, day);

CREATE TABLE visitor (
  id        TEXT PRIMARY KEY,
  first_day TEXT NOT NULL,
  last_day  TEXT NOT NULL,
  hits      INTEGER NOT NULL,
  day_hits  INTEGER NOT NULL   -- last_day 안에서의 조회수. 상한 판정용
);
CREATE INDEX visitor_first ON visitor(first_day);
```

**`visitor` 표가 따로 있는 이유는 무기한 보관 때문이다.** "이 기간에 처음 온
사람" 을 `hit` 만으로 구하면 `GROUP BY visitor` 로 전 기간을 훑어야 하고, 그 비용은
해가 갈수록 는다. 첫 방문일을 쓸 때 한 번 적어 두면 신규/재방문 판정이 인덱스 조회
하나가 된다. 복귀 여부(`last_day`)도 같은 표에서 공짜로 나온다.

`ref_kind`·`device`·`country` 는 **서버가 채운다.** 클라이언트가 보낸 값을 그대로
믿지 않는다. `country` 는 `request.cf.country` 가 공짜로 준다.

`ref_kind` 는 호스트를 네 갈래로 나눈다. 목록은 코드 안의 상수 하나다.

| 종류 | 판정 |
|---|---|
| `direct` | 호스트가 없다(주소 직접 입력, 앱 실행, 북마크) |
| `search` | `google`·`naver`·`daum`·`bing`·`duckduckgo`·`yahoo` 로 시작하는 호스트 |
| `social` | `t.co`·`x.com`·`facebook`·`instagram`·`threads`·`linkedin`·`reddit`·`youtube` |
| `link` | 나머지 전부 |

`ref` 에는 **정규화한 호스트 원본**을 그대로 넣는다(`www.` 만 뗀다). 종류가 뭉개도
호스트가 남아 있어야 "어느 블로그에서 왔나" 를 볼 수 있다.

### 5.4 KST 날짜를 쓸 때 박아 둔다

워커는 UTC 로 돈다. `day` 를 저장 시점에 KST 로 계산해 넣는 이유는 둘이다.

- **집계가 인덱스를 탄다.** `WHERE day >= ?` 는 인덱스를 쓰고,
  `WHERE datetime(ts,'+9 hours') >= ?` 는 못 쓴다(표현식 인덱스가 따로 없는 한).
- **"오늘" 이 한국 오늘이다.** 안 그러면 한국 시각 자정~오전 9시 사이의 조회가
  전날로 붙는다. 이 저장소는 이미 cron 을 KST 로 맞춰 쓰고 있다.

### 5.5 쓰기 순서

```
1) visitor upsert ... RETURNING day_hits
2) day_hits <= 500 이면 hit insert. 넘으면 건너뛴다.
```

upsert 는 날이 바뀌면 `day_hits` 를 1로 되돌린다:

```sql
INSERT INTO visitor (id, first_day, last_day, hits, day_hits)
VALUES (?1, ?2, ?2, 1, 1)
ON CONFLICT(id) DO UPDATE SET
  last_day = ?2,
  hits     = hits + 1,
  day_hits = CASE WHEN visitor.last_day = ?2 THEN visitor.day_hits + 1 ELSE 1 END
RETURNING day_hits;
```

D1 왕복 두 번, 쓰기 두 줄이다. 하루 5만 조회까지 무료 한도(10만 쓰기) 안이다.

## 6. 집계 API — `GET /api/stats`

### 6.1 인증

`Authorization: Bearer <토큰>` 을 `env.METRICS_TOKEN`(wrangler secret)과 **길이를
먼저 맞춘 뒤 상수 시간 비교**한다. 틀리면 `401` 과 `{ 오류: "인증" }` 만 낸다 —
숫자는 한 톨도 안 나간다. 잠금은 화면이 아니라 여기에 있다.

### 6.2 한 번에 다 준다

화면이 여섯 번 왕복하며 그려지는 것을 막는다. **화면에서 본 왕복은 한 번**이다.
워커 안에서는 질의 열한 개를 `Promise.all` 로 동시에 보내 한 덩어리로 조립한다
(`batch()` 도 되지만, 각 질의가 서로 다른 SQL 이라 묶어서 얻는 것이 없고 대역을
씌우기만 어려워진다).

```json
{
  "기간": { "시작": "2026-08-13", "끝": "2026-09-11", "일수": 30 },
  "요약": { "방문자": 0, "세션": 0, "조회": 0, "신규": 0, "재방문": 0 },
  "직전": { "방문자": 0, "세션": 0, "조회": 0 },
  "도메인": [{ "도메인": "employment", "방문자": 0, "세션": 0, "조회": 0, "직전방문자": 0 }],
  "일별": [{ "날짜": "2026-08-13", "방문자": 0, "도메인별": { "employment": 0 } }],
  "화면": [{ "도메인": "employment", "경로": "/b/industry/:id", "조회": 0, "방문자": 0 }],
  "유입": { "종류": [{ "종류": "search", "세션": 0 }], "호스트": [{ "호스트": "google.com", "세션": 0 }] },
  "기기": [{ "값": "mobile", "방문자": 0 }],
  "표시모드": [{ "값": "standalone", "방문자": 0 }],
  "국가": [{ "값": "KR", "방문자": 0 }]
}
```

키는 한국어다 — ask 워커가 이미 그렇게 한다(`답변`, `배지`, `한계`).

- **방문자**는 `COUNT(DISTINCT visitor)`, **세션**은 `COUNT(DISTINCT session)`,
  **조회**는 줄 수다. 도메인별 방문자를 다 더해도 전체 방문자와 안 맞는다 — 한 사람이
  두 도메인을 보면 양쪽에 한 번씩 세어지기 때문이다. **이건 버그가 아니고, 화면이
  그렇게 말해야 한다**(§7.2).
- **직전**은 같은 길이의 바로 앞 기간이다(30일이면 그 앞 30일).
- **신규**는 `visitor.first_day` 가 기간 안에 드는 방문자, **재방문**은 그 나머지다.
- 화면·호스트는 상위 20·10 까지만.
- `days=0` 은 전 기간이다.

### 6.3 유입은 세션의 첫 줄만 센다

세션 안의 내부 이동은 referrer 가 같은 사이트라 안 보내지고(§4.3), 그래서 `direct`
로 기록된다. 이 줄들을 같이 세면 **구글에서 들어와 세 화면을 돈 세션 하나가
`search` 에도 `direct` 에도 세어진다** — 종류별 합이 실제 세션 수보다 커지고,
직접 유입이 실제보다 부풀려진다. 설계 중 프로토타입으로 재현해 확인했다.

그래서 유입 집계만 세션의 **첫 줄**로 좁힌다.

```sql
SELECT ref_kind 종류, COUNT(*) 세션 FROM (
  SELECT session, ref_kind, MIN(id) FROM hit WHERE day BETWEEN ?1 AND ?2 GROUP BY session
) GROUP BY ref_kind ORDER BY 세션 DESC;
```

`MIN(id)` 옆의 `ref_kind` 는 **최솟값이 나온 그 행의 값**이다. SQLite 가 `min()`/
`max()` 단일 집계에 대해 보장하는 동작이고 D1 은 SQLite 다. 다른 DB 로 옮기면
깨지는 자리라 옮길 일이 생기면 여기부터 본다. 호스트 집계도 같은 하위질의를 쓴다.

이 보정은 유입에만 적용한다. 기기·표시모드·국가는 방문자 단위라 무관하다(다만 한
사람이 폰과 PC 로 보면 양쪽에 세어진다 — §11).

## 7. 관리자 화면 — `domains/admin/app/`

### 7.1 자리와 껍데기

`build.py` 가 `domains/*/app` 을 자동으로 찾으므로 폴더만 만들면
`/employ_archive/admin/` 이 생긴다. 허브 카드 목록은 `hub/js/state.js` 의 `DOMAINS`
하드코딩이라 **저절로 노출되지 않는다** — 그대로 둔다.

`manifest.webmanifest` 와 `sw.js` 는 **안 붙인다.** 설치할 물건도, 오프라인에서 볼
물건도 아니다. 서비스워커를 붙이면 허브의 `hub-` 접두사 규칙과 캐시 정리만 복잡해진다.

셸 규칙은 그대로 따른다: `core/tokens.css`·`core/base.css`,
`.app { height: 100dvh }`(`min-height` 로 되돌리면 헤더가 밀려 나간다), 헤더 제목은
`방문 현황` 으로 **고정**하고 허브로 가는 홈 버튼을 둔다.

### 7.2 한 페이지, 위에서 아래로

1. **기간 세그먼트** — 7일 / 30일 / 90일 / 전체. 기본 30일
2. **요약 줄** — 방문자 · 세션 · 조회. 각각 직전 동기간 대비 증감
   (`.delta-up`/`.delta-down` 토큰 재사용)
3. **도메인별 카드 여섯** — 방문자수 내림차순. 조회수·점유율 막대·증감.
   아래에 한 줄: *"한 사람이 두 도메인을 보면 양쪽에 세어진다 — 합계가 전체보다 크다"*
4. **일별 추이** — 도메인별 색 누적 막대
5. **화면 상위 20** — 도메인 배지 + 경로 + 조회수 막대
6. **유입** — 종류 넷(직접·검색·소셜·링크) + 호스트 상위 10
7. **기기 · 표시모드 · 국가** — 작은 가로 막대 셋.
   표시모드는 이 프로젝트에서 특히 의미가 있다(앱으로 설치해 쓰는지)
8. **신규 대 재방문**
9. **내 방문 제외 스위치**, **토큰 지우기**

### 7.3 그림은 순수 함수로

`domains/employment/app/js/chart.js` 와 `domains/press/app/js/graph.js` 가 둘 다
**SVG 문자열만 만들고 DOM 을 안 만진다.** 그래서 좌표 불변식을 테스트가 지킨다.
`domains/admin/app/js/chart.js` 도 같은 규율을 따른다.

도메인 여섯의 색은 구현 시 `dataviz` 스킬을 읽고 정한다. `core/tokens.css` 에는
계열색(`--up`/`--down`/`--accent`)만 있고 범주형 팔레트가 없다.

### 7.4 잠금과 제외 스위치

- 토큰이 없으면 화면 전체가 **입력 한 칸**이다. 넣으면 `localStorage['ea:token']` 에
  두고 이후 자동으로 붙인다.
- `401` 이 오면 저장한 토큰을 지우고 입력 화면으로 돌아간다.
- 워커에 못 닿으면 **"서버에 연결하지 못했다"** 와 **"아직 배포되지 않았다"** 를
  구분해 말한다. 엔드포인트가 아직 자리표시자면 후자다 — ask 에서 이 구분이 없어
  배포 미완료를 네트워크 장애로 읽은 적이 있다(`domains/ask/DEPLOY.md`).
- 제외 스위치는 `localStorage['ea:off']` 를 켜고 끈다. 같은 오리진이라 여섯 앱에
  한 번에 적용된다(§4.5). 지금 켜져 있는지를 화면이 보여 준다.

## 8. 배포 — `domains/admin/DEPLOY.md`

사람이 로컬에서 한 번 돈다. GitHub Actions 는 아무것도 안 해 준다.

```bash
cd domains/admin/worker
wrangler d1 create employ-archive-metrics          # → database_id 를 wrangler.jsonc 에
wrangler d1 execute employ-archive-metrics --remote \
  --config wrangler.jsonc --file=migrations/0001_init.sql
wrangler secret put METRICS_TOKEN                   # 관리자 비밀번호
wrangler deploy                                     # → workers.dev 주소를 받아 적는다
```

받은 주소를 **두 군데**에 넣는다: `core/track.js` 의 `ENDPOINT`,
`domains/admin/app/js/api.js` 의 `API`. 그 다음 병합하면 `pages.yml` 이 돈다.

**순서를 뒤집어도 안전하다.** 워커가 아직 없으면 비콘이 조용히 실패할 뿐 앱은 멀쩡하고,
관리자 화면은 §7.4 의 "아직 배포되지 않았다" 를 낸다. ask 와 달리 사용자 눈에 보이는
기능이 깨지지 않는다.

## 11. 한계 (화면이 아니라 여기에 적어 둔다)

- **광고 차단기가 막으면 그 방문은 없는 것이 된다.** 자체 도메인이 아니라
  `*.workers.dev` 라 차단 목록에 오를 여지가 있다. 모든 숫자는 하한이다.
- **localStorage 를 지우면 같은 사람이 새 방문자가 된다.** 재방문율도 하한이다.
- 기기 구분은 UA 추정이고, 국가는 Cloudflare 의 IP 추정이다.
- 봇 필터는 **자칭 봇만** 거른다. JS 를 돌리면서 UA 를 숨기는 것은 못 거른다.
- 도메인별 방문자의 합은 전체 방문자보다 크다(§6.2).
- **세션은 `sessionStorage` 수명이지 30분 유휴가 아니다.** 탭을 안 닫고 하루를 두면
  한 세션이고, 설치앱(standalone)은 특히 길다. 세션 수는 일반 웹분석 도구의 세션보다
  적게 나온다 — 도구 간 숫자를 비교하지 않는다. 유휴 규칙은 필요해지면 그때 넣는다.
