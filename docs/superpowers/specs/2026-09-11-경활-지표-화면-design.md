# 경활 지표 화면 — 설계

2026-09-11. 브랜치 `employment/release-summary` 이어서.

## 무엇을

총괄에서 경활 카드를 누르면 나오는 화면(`#/r/eaps`)에, 경제활동인구조사가
발표하는 **주요 지표를 시계열로** 얹는다. 지금 그 화면에는 카드·보도자료
요약·속성별 상위가 있고, 숫자는 취업자수 하나뿐이다.

예상안을 실제 2026-08 자료로 만들어 사용자가 보고 결정했다
(`https://claude.ai/code/artifact/954b9d2e-d13f-4e7c-b3d8-601dc9438f64`).

## 사용자가 정한 것

1. **한 출처(경활)만 먼저.** 사업체·행정통계는 이 화면을 보고 넓힌다.
2. **KPI 4 + 추이 6.** KPI 는 보도자료가 앞세우는 넷(15~64세 고용률·청년층
   고용률·실업률·청년층 실업률), 추이는 총괄 6지표(취업자·실업자·고용률·
   실업률·경활참가율·비경활인구).
3. **한 줄 스크롤.** 지표가 주인공이고 보도자료 요약·속성별 상위는 접어 둔다.
4. **그래프는 수준 선 + 증감 막대의 이중축.** 선 아래 음영은 뺀다.
5. **스크럽 라벨.** 그래프에서 시점을 움직이면 그 달의 시점·수준·증감이 뜬다.

지표를 더 넣거나 빼는 일은 나중에 한다(사용자 판단).

## 왜 지금 되는가

세 출처 모두 **이미 매달 받는 파일 안에** 주요 지표가 들어 있다. 새 출처도
새 네트워크 호출도 없다. 경활은 특히 쉽다:

`1.전체`·`1564`·`1529` 세 시트가 **레이아웃이 완전히 같다** — 열이
`인구 · 경제활동인구 · 취업자 · 실업자 · 비경제활동인구 · 참가율 · 고용률 ·
실업률` 순이다. 증감도 `1.전체증감`·`1564증감`·`1529증감` 으로 짝이 맞고 같은
배치다. 파서 하나가 (시트, 범위) 쌍 여섯을 돌면 끝난다.

**증감은 증감 시트에서 읽는다.** 우리가 전년동월 값에서 빼서 만들지 않는다 —
원문이 이미 갖고 있고, 계산하면 반올림이 원문과 어긋난다. 실측으로 확인했다:
2026-08 취업자 증감 시트 값 184.0천명 = 보도자료 요약의 "18만 4천명 증가".

월 행은 회차마다 28개인데 앞쪽 넷은 연도별 8월이라 띄엄띄엄하다. **연속
구간만 쓴다**(2026-08 회차 기준 2024-08~2026-08, 25개월).

## 데이터 모델 — 지표 축을 세운다

`SeriesRecord.series` 가 이미 있고 지금은 전부 `headcount` 다. 여기에 지표를
채운다.

| series | 뜻 | unit | yoy 의 뜻 |
|---|---|---|---|
| `headcount` | 취업자수 (기존 레코드 전부) | 천명 | 천명 증감 |
| `unemployed` · `labor_force` · `inactive` · `population` | 실업자·경활인구·비경활·15세이상인구 | 천명 | 천명 증감 |
| `employment_rate` · `unemployment_rate` · `participation_rate` | 고용률·실업률·참가율 | % | **%p 차이** |

연령 범위는 속성 축에 싣는다. 전체(15세 이상)는 지금처럼 `breakdown='total'`,
15~64세·15~29세는 **`breakdown='scope'`, `category='15-64'|'15-29'`**.

연령 속성(`age`)에 넣지 않는 이유: 15~64세는 연령 구간들을 가로질러서 속성별
매트릭스에 들어가면 이중 계상으로 읽힌다. `scope` 는 속성별 화면이 쓰지 않는
별도 축이다.

### 먼저 고칠 것 — `make_id`

```python
def make_id(source, period, breakdown, category):
    return f"{source}-{period}-headcount-{breakdown}{tail}"   # headcount 가 박혀 있다
```

지표가 둘 이상이 되는 순간 고용률과 취업자수가 같은 id 를 갖고, `store.upsert`
가 둘을 같은 관측으로 보고 서로 덮어쓴다. 지표를 인자로 받아 넣는다. 기존
레코드의 id 는 한 글자도 안 바뀐다(`-headcount-` 가 이미 그 자리다).

## 화면이 지표를 거르지 않는 문제

`data.js` 의 조회가 전부 `series` 를 안 본다:

```js
const totals = series.filter(r => r.source === code && r.breakdown === 'total');
```

새 레코드가 들어오는 순간 총괄 카드·속성별 매트릭스·시트·속성별 상위가
**엉뚱한 레코드를 집는다**(총괄 카드가 취업자수 자리에 고용률 63.3 을 그리는
식이다). 그래서 **데이터를 늘리기 전에** 필터를 넣고 테스트로 못박는다.

## 단위를 모르는 포맷터

`fmtLevel`/`fmtDelta` 는 천명→만명 변환을 무조건 한다. 고용률 63.3 을 넣으면
`6.3만명` 이 된다. 레코드의 `unit` 을 보고 갈라지는 포맷터를 새로 둔다:

- `천명` → 만명 한 자리, 증감도 만명
- `%` → 퍼센트 한 자리, 증감은 **%p**

## 그림 — 수준 선 + 증감 막대

한 그림, 한 x축, 두 개의 y 척도.

- **위쪽 띠**: 수준 선(2px, accent). 0 기준이 아니라 그 구간의 최저~최고에
  맞춘다. 추세를 보는 그림이지 크기를 재는 그림이 아니다.
- **아래쪽 띠**: 전년동월대비 증감 막대. **0선 기준 대칭**이고, 증가/감소를
  부호색(`--up`/`--down`)으로 가른다.
- 두 띠를 겹치지 않게 나눈다. 겹쳐 그리면 두 축의 눈금을 맞출 수 없어 "선이
  막대를 뚫고 지나가는" 착시가 생긴다.
- 각 축의 실제 범위를 그림 밖에 글자로 적는다. 눈금선은 긋지 않는다(좁다).
- 선 아래 음영은 없다(사용자 판단 — 막대와 같이 놓으면 어수선하다).

### 스크럽 라벨

그림을 누르거나 끌면 가장 가까운 달에 세로선이 서고, 그 달의 **시점 · 수준 ·
증감**이 그림 위 라벨로 뜬다. 손을 떼도 남는다(읽으라고 띄운 것이다).

좌표 계산은 `chart.js` 의 순수 함수가 맡는다 — 이미 `periodAtRatio` 가 같은
일을 하고 있고, 화면 코드에 두면 그림과 어긋나는 날이 온다.

이건 상위 스펙 7.6 의 보류 항목(툴팁·crosshair·시계열 값 라벨)을 이 화면에서
먼저 갚는 것이다. 하단 시트에도 같은 것이 필요하지만 이번엔 건드리지 않는다.

## 화면 구성

```
← 총괄 · 연월 스위처
카드 (지금 그대로)
주요 지표          KPI 4장 (2×2)
최근 N개월 추이     수준+증감 그림 6개
▸ 보도자료 요약     (접힘)
▸ 가장 크게 움직인 곳 (접힘)
```

## 순서

1. `make_id` 에 지표를 넣고 `data.js` 전 조회에 `series==='headcount'` 를
   넣는다. **데이터는 아직 안 늘린다** — 기존 테스트가 전부 통과해야 한다.
2. 수집기에 `parse_totals` 를 붙이고 실제로 돌려 `series.json` 을 늘린다.
3. `chart.js` 에 그림과 좌표 함수, `data.js` 에 지표 조회와 포맷터.
4. `release.js` 에 KPI·추이·접기.

## 건드리지 않는 것

`store.upsert` 의 병합 규칙, KOSIS 대조 가드, 하단 시트, 속성별 화면의 매트릭스,
다른 도메인. 사업체·행정통계 수집기.
