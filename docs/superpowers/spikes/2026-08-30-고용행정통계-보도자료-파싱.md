# 스파이크: 고용행정통계 보도자료 자동 수집 가능성

일자: 2026-08-30
질문: 고용노동부 보도자료 게시판에서 최신 회차를 자동으로 찾아 hwpx 첨부를 받고,
      상시가입자 총량·산업별 수치를 파싱할 수 있는가?

## 결론

**가능하다.** 네 단계가 전부 뚫렸고, 새로운 의존성이 필요 없다(파이썬 표준
라이브러리 `zipfile` + `xml.etree` 로 충분). 다만 표를 **인덱스로 찾으면 안 된다**
— 아래 5장 참조.

## 1. 게시판 검색 — POST

`https://www.moel.go.kr/news/enews/report/enewsList.do`

GET 파라미터로는 필터가 걸리지 않는다. 폼(`id=frm`)이 POST이며 `bbs_id` 가 필수다.

```python
data = {"pageIndex": "1", "bbs_id": "12", "searchField": "1",
        "searchText": "고용행정통계", "pageUnit": "30"}
r = requests.post(URL, data=data, headers={"Referer": URL, ...})
```

`searchField` 는 `1`=제목 / `2`=내용 / `3`=전체. 제목 검색으로 충분하다.

결과 30건이 전부 `YYYY년 M월 고용행정 통계로 본 노동시장 동향` 형식이고 최신순이다.
**제목에 기준월이 들어 있으므로 발표일을 따로 파싱할 필요가 없다.**

목록 HTML 에서 `news_seq=(\d+)` 로 회차 번호를 얻는다.

## 2. 첨부 링크 — 상세페이지에 명시

`enewsView.do?news_seq=<seq>` 안에 확장자가 파라미터로 박혀 있다.

```
/common/downloadFile.do?file_seq=...&bbs_seq=19759&bbs_id=12&file_ext=hwpx
/common/downloadFile.do?file_seq=...&bbs_seq=19759&bbs_id=12&file_ext=pdf
```

`file_ext=hwpx` 로 정규식 한 번이면 된다. 파일명 추측이 필요 없다.
다운로드 시 해당 상세페이지를 `Referer` 로 보낸다.

## 3. hwpx 구조 — 표준 ZIP

`Contents/section0.xml` 단일 섹션. 표는 `<hp:tbl>` → `<hp:tr>` → `<hp:tc>`,
텍스트는 `<hp:t>`. 2026년 7월분 기준 표 108개.

## 4. 목표 표

| 표 | 내용 | 단위 |
|---|---|---|
| 수준 (1번째 후보) | 상시가입자수 — 전산업 + 산업 대분류 | 천명 |
| 수준 이어지는 표 | 나머지 산업 열 (정보통신업~기타) | 천명 |
| 증감 (2번째 후보) | 전년동월대비 증감 — 전산업 + 산업 대분류 | 천명 |
| 증감 이어지는 표 | 나머지 산업 열 | 천명 |

**산업 열이 한 표에 다 안 들어가 다음 표로 이어진다.** 앞 표에 전산업·농림어업·
제조업·전기가스·건설업·서비스업·수도하수폐기업·도소매·운수창고·숙박음식,
뒤 표에 정보통신업·금융보험·부동산업·전문과학기술·사업서비스·공공행정·
교육서비스·보건복지·예술스포츠·협회개인서비스·기타. 두 표를 합쳐야 대분류가 완성된다.

행 구조: 0~1행이 2단 헤더, 2행부터 연도(2019~), 이후 월. **마지막 행이 최신월.**

`참고2` 표에 **부호 ↔ 약칭 산업분류명 ↔ 표준산업분류명** 매핑이 통째로 들어 있다
(A=농림어업, C=제조업, F=건설업 …). `industries.json` 을 손으로 만들지 않아도 된다.

## 5. 함정 — 표 인덱스가 달마다 밀린다

3개월치를 대조한 결과:

| 회차 | 표 개수 | 목표 표 인덱스 |
|---|---|---|
| 2026-07 | 108 | 64, 66 |
| 2026-06 | 108 | 64, 66 |
| 2026-05 | 107 | 63, 65 |

**인덱스로 찾는 파서는 언젠가 조용히 다른 표를 읽는다.** 헤더 내용으로 찾아야 한다:

```python
cand = [i for i, g in enumerate(tables)
        if g and len(g[0]) > 5
        and all(k in " ".join(g[0]) for k in ("전산업", "농림어업", "제조업"))]
level, delta = cand[0], cand[1]   # 첫 쌍이 수준, 둘째 쌍이 증감
```

이 방법으로 세 달 모두 정확히 찾았다:

| 회차 | 수준 전산업 | 증감 전산업 |
|---|---|---|
| 2026-07 | 15,877 | 277 |
| 2026-06 | 15,855 | 264 |
| 2026-05 | 15,848 | 268 |

수준과 증감은 헤더가 동일하므로 **순서로만 구분된다.** 안전장치로 크기 검증을 둔다:
수준의 전산업은 10,000 이상, 증감의 전산업은 절댓값 1,000 미만.

## 6. 내장된 검증 대조점

p1 `<주요 특징>` 박스에 총량 증감이 문장으로 나온다:

> ‘26.7월 고용보험 가입자는 **27만 7천명** 증가

증감 표의 전산업 마지막 값 `277`(천명)과 일치한다. **수집기가 파싱 결과를 스스로
검증할 수 있다.** 불일치하면 서식이 바뀐 것이므로 수집을 실패시키고 사람을 부른다.

## 7. 과거 수치가 개정된다

2026년 6월 상시가입자 수준이 6월 발표본에서는 `15,855`, 7월 발표본에서는 `15,856` 이었다.
잠정치가 나중에 조정된다는 뜻이다.

C단계 설계 반영 사항: 같은 `(source, period, breakdown, category)` 레코드를 **덮어쓰되**
`released_at` 을 함께 갱신한다. 전망 도메인처럼 회차별 이력을 쌓지 않는다 —
실적 통계에서 중요한 것은 최신 확정값이지 개정 이력이 아니다.

## 9. 덧붙임 — KOSIS 산업 대분류 시계열 확인 시도 (미확정)

스펙 11장의 가정("KOSIS OpenAPI 에 경활·사업체노동력조사의 월별 산업 대분류
시계열이 제공된다")을 확인하려 했으나 **결론을 내지 못했다.**

키 없이 접근 가능한 통계 MCP로 조회한 결과:

- KOSIS API 자체는 정상 동작하고 메타데이터 구조가 깔끔하다 —
  `항목(ITM_ID)` + `분류(objL1/objL2/…)` 코드 체계, 월별(`periodType: M`) 지원
- 그러나 이 경로로 찾아지는 경제활동인구조사 통계표는 전부 성·연령·교육정도·
  취업시간·종사상지위·시도로 잘려 있고 **산업 차원을 가진 표가 나오지 않았다**
  (확인한 표: DT_1DA7012, DT_1DA7014S, DT_1DA7104S 및 검색 결과 15건)
- MCP 의 자연어 라우팅도 산업 단위를 지원하지 않는다

**이것은 KOSIS 에 해당 표가 없다는 증거가 아니다.** 이 MCP 의 검색 범위 한계다.
확정하려면 KOSIS 오픈API 키로 `statisticsList.do` 를 경제활동인구조사로 좁혀
직접 조회해야 한다. 키는 수집기 구현에 어차피 필요하다.

### 확정 (키 발급 후 실측)

| 대상 | 통계표 | 결과 |
|---|---|---|
| 경활 **원계열** 산업별 취업자 | `101/DT_1DA7E06S` | ❌ **2024년 12월에서 종료.** 2026년 조회 시 `데이터가 존재하지 않습니다` |
| 경활 **계절조정** 산업별 취업자 | `101/DT_1DA9003S` | ⚠️ 현행(최신 202607), 대분류 21개(A~U), 천명 |
| 사업체노동력조사 종사자 | `118/DT_118N_MON066` | ✅ 현행(최신 202606), 단위 명 |

**경활의 원계열 월별 산업별 표는 KOSIS API 로 얻을 수 없다.** 살아 있는 것은
계절조정 표뿐인데, 계절조정치는 원계열과 다른 수치다. 고용행정통계(원계열)와
나란히 놓으려면 원계열이어야 하므로 **경활도 보도자료 파싱으로 간다.**
(`DT_1DA7E26S` 성/산업별도 같은 202412 에서 멈춰 있음을 확인했다.)

사업체노동력조사는 API 로 간다. 다만 `DT_118N_MON066` 은 대분류와 중분류가 한
축에 섞여 90개 항목으로 나온다(`B.광업(05~08)` 다음에 `석탄 원유 및 천연가스 광업`
…). **대분류만 골라내는 필터가 필요하다** — 대분류 항목은 `부호.명칭(코드범위)`
형식이라는 규칙을 쓴다.

### 발표 시차가 출처마다 다르다

같은 날 조회했는데 최신 시점이 갈렸다:

| 출처 | 최신 시점 |
|---|---|
| 고용행정통계 | 2026-07 |
| 사업체노동력조사 | 2026-06 |

**총괄 화면의 기준월 스위처는 출처마다 최신월이 다른 상황을 다뤄야 한다.**
가장 최신월을 고르면 아직 발표되지 않은 출처가 생기므로, 그 카드는 미제공이
아니라 **"미발표"** 로 구분해 표시한다. 미제공(그 출처가 원래 안 잡는 산업)과
미발표(아직 안 나온 달)는 다른 상태다.

### C단계 수집 방식 확정

| 수집기 | 대상 | 방식 |
|---|---|---|
| `eaps_press.py` | 경제활동인구조사 | 보도자료 hwpx 파싱 (원계열 확보 위해) |
| `est_kosis.py` | 사업체노동력조사 | KOSIS OpenAPI `118/DT_118N_MON066` |
| `ei_press.py` | 고용행정 통계로 본 노동시장 동향 | 보도자료 hwpx 파싱 |

hwpx 파서를 두 출처가 공유하므로 1~7장의 검증이 그대로 재사용된다.

## 10. 경활 보도자료(국가데이터처) — 해결

`kostat.go.kr` 은 **`mods.go.kr`**(국가데이터처)로 리다이렉트된다.
고용·노동 분야 보도자료 게시판이 따로 있고, 통합 게시판 검색으로는 안 잡힌다.

```
https://mods.go.kr/board.es
  ?mid=a10301030100&bid=a103010301&ref_bid=210,211,11109,11113,11814
```

GET 한 번이면 목록이 나온다. **검색이 필요 없다** — 이 게시판은 고용·노동
보도자료만 담고 있어 `고용동향` 이 제목에 든 항목을 고르면 된다.
`bid=210` 이 경제활동인구조사다.

### 첨부 링크

목록 페이지에 첨부가 바로 붙어 있고, `class` 속성이 확장자를 알려준다:

```html
<a href="/boardDownload.es?bid=210&list_no=446465&seq=4" class="bf_xlsx">
  <span class="hdn">26년 7월 고용동향의 xlsx파일</span></a>
```

정규식 하나로 제목·확장자·링크를 동시에 얻는다. 제목(`26년 7월 고용동향`)에
기준월이 들어 있어 날짜를 따로 파싱할 필요가 없다. 한 회차의 첨부는
pdf(본문) / hwpx(본문) / pdf(통계표) / **xlsx(통계표)** 네 개다.

### xlsx 를 쓴다 — hwpx 가 아니라

hwpx 본문에도 표가 있지만 **xlsx 가 압도적으로 낫다.** 시트 42개가 통계표별로
나뉘어 있고 이름이 곧 내용이다:

| 시트 | 내용 |
|---|---|
| `3.산업(신)` | 산업별 취업자 **수준** |
| `3.산업(신) (2)` | 이어지는 산업 열 |
| `3.산업증감(신)` | 산업별 취업자 **증감** |
| `3.산업증감(신) (2)` | 이어지는 산업 열 |

MOEL 처럼 표 순서를 내용으로 추정할 필요가 없다 — **시트 이름으로 직접 집는다.**
열이 넘쳐 `(2)` 로 이어지는 구조는 MOEL 과 동일하다.

헤더는 4~6행에 걸친 다단이고(전체 취업자 / 농림어업 / 광공업 / 제조업 /
사회간접자본 및 기타서비스 / 전기,가스 / 수도,하수,폐기물 / 건설업 …),
데이터는 연도 행부터 시작해 월 행이 이어진다. 값은 천명 단위 실수다.

xlsx 파싱에도 새 의존성이 필요 없다 — ZIP 안의 `xl/sharedStrings.xml` 과
`xl/worksheets/sheetN.xml` 을 `zipfile` + `xml.etree` 로 읽으면 된다.

### 놓칠 뻔한 함정 — hwpx 는 섹션이 여러 개일 수 있다

경활 hwpx 는 `Contents/section0.xml`, `section1.xml`, `section2.xml` 세 개다.
본문 표는 3.1MB 짜리 `section2.xml` 에 있고, `section0` 만 읽으면 표지·일러두기·
목차만 나온다(실제로 처음에 그렇게 읽어 "표가 9개뿐"이라고 잘못 판단했다).

MOEL 자료는 마침 `section0` 하나뿐이라 문제가 드러나지 않았다.
**hwpx 파서는 `Contents/section*.xml` 을 전부 읽어야 한다.**

## 11. 세 출처 수집 경로 — 최종

| 출처 | 경로 | 형식 |
|---|---|---|
| 경제활동인구조사 | `mods.go.kr` 게시판(`bid=210`) → xlsx 첨부 | 시트 이름으로 선택 |
| 사업체노동력조사 | KOSIS OpenAPI `118/DT_118N_MON066` | JSON |
| 고용행정통계 | `moel.go.kr` 게시판(`bbs_id=12`) → hwpx 첨부 | 표 내용으로 탐색 |

전부 표준 라이브러리로 처리된다(`requests` 는 이미 의존성에 있다).
